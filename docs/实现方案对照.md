# 与《CHZUyyd 安卓版执行方案》的对照

> 方案原文：`C:\Users\Lenovo\Documents\CHZUyyd-安卓版执行方案.md`
> 本文说明 CHZUyyd 安卓版如何落地该方案，以及做了哪些取舍。

## 1. 路线选择

方案推荐“路线 A（Kivy）MVP → 按需升级 B1（Compose + Chaquopy）”。
本项目**直接采用 B1 路线**，原因：

1. 目标机需要长期后台定时，原生 `AlarmManager` + 前台服务比 Kivy 更可靠；
2. 本机具备 JDK 21 + Android SDK 35 + Python 3.14，Chaquopy 17.1
   官方支持 Python 3.14 / AGP 8.7，构建链已验证；
3. 协议层仍是纯 Python，和方案阶段 0 的 `proto/` 设计一致；
4. UI 用 Compose，比 Kivy 更贴近 Android 交互，也避免输入法/字体问题（方案 R4）。

## 2. 阶段 0：协议层抽取

| 方案要求 | 落地 |
|---|---|
| `proto/crypto.py` | `python/proto/crypto.py` |
| `proto/http.py` | `python/proto/http.py`（urllib，替代 pycurl） |
| `proto/login.py` | `python/proto/login.py` |
| `proto/history.py` | `python/proto/history.py` |
| `proto/run.py` | `python/proto/run.py` |
| `proto/config.py` | `python/proto/config.py` |
| 不使用 winreg/ctypes/tkinter/subprocess/sys.executable | ✅ 协议层无这些 import |
| 路径参数化，不 os.chdir | ✅ 任务目录由 Kotlin 传入 |
| 进度回调，不 print/tqdm | ✅ `onProgress(json)` / `ProgressSink` |
| 不用 input/exit | ✅ 异常 + JSON 结果 |
| 保持 `__RESULT__` JSON 契约 | ✅ `proto/api.py` 全部返回 JSON 字符串 |
| 依赖清零 | ✅ 无 pip 依赖：gmssl 子集随包 + 标准库 urllib |

> 与方案的差异：方案建议 `requests`；本项目用标准库 `urllib` 实现同样的
> POST/gzip/关闭证书校验语义，少一个依赖，APK 更小。

## 3. 阶段 1：MVP 壳 + 手动功能

| 方案要求 | 落地 |
|---|---|
| buildozer 工程骨架 | 改为 Android Gradle + Chaquopy（B1） |
| 4 个页面 | 实际 5 个：账号 / 历史 / 跑步 / 日志 / 设置 |
| 进度条 + 剩余时间 | Compose `LinearProgressIndicator` + `Notify.formatTime` |
| 私有目录存储 | `filesDir/tasks_CHZU`、`files/logs`、SharedPreferences |
| 权限与网络配置 | INTERNET、通知、精确闹钟、电池优化、前台服务 |
| debug APK | ✅ `dist/CHZUyyd-v1.0.0-debug.apk` |

## 4. 阶段 2：后台定时

| 方案要求 | 落地 |
|---|---|
| 调度层移植 | `ScheduleLogic.kt`（纯逻辑 + JVM 单测） |
| `setExactAndAllowWhileIdle` | `AlarmScheduler.kt`，无权限时退化 `setAndAllowWhileIdle` |
| 前台服务 + 通知栏进度 | `RunService.kt`，`dataSync` 类型 + 常驻通知 + WakeLock |
| `BOOT_COMPLETED` 恢复 | `BootReceiver.kt`（开机 / 改时间 / 改时区） |
| 电池优化引导 | 设置页跳 `ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` |
| 失败重试 / 补跑 | 补跑窗口 2/5/15/30/60 分钟；失败保留记录并重排下一次（与桌面版一致） |
| 锁屏/省电验收 | 与 BBUyyd 版共享同一套已实测的调度代码；CHZU 版本未重复锁屏实测，OEM 真机待测 |

## 5. 阶段 3：打包与交付

| 方案要求 | 落地 |
|---|---|
