## 3. 模拟器实测

### 3.1 安装与启动

- `adb install app-debug.apk` 成功；
- 首次启动弹出通知权限；允许后进入「账号」页；
- `files/tasks_CHZU` 首次只有 `说明.txt`，**不内置任何轨迹**；
- Python 3.14 初始化成功（无 FATAL，无导入错误）；
- release 通用包卸载 debug 后安装成功，启动正常。

### 3.2 真实账号登录

- 输入滁州学院学号/密码 → 登录状态变为 **已登录**；
- 日志：`开始登录：2025…（滁州学院）` → `登录成功`；
- token 写入 SharedPreferences，重启后仍在；
- 登录接口：`https://tiyu.chzu.edu.cn:8010/m-api/login/appLoginCHZU`。

> 本次真实登录会让手机端云运动下线；这是桌面版同样存在的行为。

### 3.3 历史数据

- 获取学期列表：**9 个**；
- 当前学期跑步记录：**8 条**；
- 初始 `tasks_CHZU`：0 条；
- 抓取记录：保存为 `tasklist_0.json`，**2.22 km**；
- 保存后轨迹列表从 0 条变为 1 条；
- 日志：`抓取完成：.../tasklist_0.json，距离 2.22 km`。

### 3.4 删除轨迹

- 点轨迹右侧删除图标 → 弹窗“确定删除 tasklist_0.json 吗？”→ 删除；
- `files/tasks_CHZU` 只剩 `说明.txt`；日志：`已删除轨迹：tasklist_0.json`；
- 再次抓取 1 条 → 点「清空全部」→ 确认 → `全部删除`；
- 日志：`已清空历史轨迹：共删除 1 条`；列表回到 0 条；
- 删除后「开始自动执行 / 立即执行」提示“还没有轨迹数据，请先抓取”，
  不会启动空跑。

### 3.5 定时与后台

CHZU 版的 `AlarmScheduler` / `RunService` / `BootReceiver` 与 BBUyyd 版
**代码完全一致**，已在 BBUyyd 版完成以下实测：

- `AlarmManager.setExactAndAllowWhileIdle` 注册；
- 锁屏 + App 后台状态下闹钟准时触发；
- 前台服务启动并调用 Python；
- 失败后自动重排下一次；
- 目标次数/补跑逻辑通过 Kotlin 单元测试。

CHZU 版本次未重复做锁屏闹钟实测；正式使用前建议在允许跑步时段做一次
「立即执行一次」与一次定时触发验证。

## 5. 风险与后续

1. **允许时段实测**：在滁州学院允许跑步的时段完成一次真实跑步，
   确认 `/run/start` 返回 `canSport=Y`、进度条/通知/记录正常。
2. **OEM 真机**：小米/华为/OPPO/vivo 各一台，锁屏 30 分钟 + 省电模式，
   连续 3 天验证；必要时加入电池白名单。
3. **Keystore 加密**：密码/token 当前为私有目录明文，后续可用 Android
   Keystore AES/GCM 加密。
4. **精确闹钟权限**：真机按设置页跳转授权；未授权时退化为非精确闹钟，
   补跑窗口兜底。
5. **成功跑步后的服务器记录**：本次未执行真实跑步。
